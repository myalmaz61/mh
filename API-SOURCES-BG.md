# MyHub Football — източници и ограничения (23.11.2026)

## Защо добавихме втори източник

OpenLigaDB попълва резултати чрез общността. Понякога дадена среща остава непотвърдена, независимо колко често MyHub проверява. Затова v2.5.0 запазва OpenLigaDB и предлага допълнителна справка по дата с SportScore.

## SportScore

- Официална документация: https://sportscore.com/developers/api/
- Условия за безплатни приложения: https://sportscore.com/developers/terms/
- Ендпойнт в тази версия: `GET https://sportscore.com/api/v1/fixtures/?sport=football&date=YYYY-MM-DD&limit=200`.
- Документацията го описва като анонимен JSON endpoint. Публичният API е заявен като CORS-open.
- Условието за видима атрибуция е спазено: `<a href="https://sportscore.com/" rel="dofollow" title="Sports data by SportScore">Powered by SportScore</a>`.
- При непознат формат на API отказваме да показваме резултати вместо да правим догадки. Непотвърденият статус не е резултат „FT“.
- Функцията е по избор и **не изисква собствен backend**. Няма акаунт, private API key, реклами или tracking код.

## Защо не football-data.org или TheSportsDB като основен източник?

- football-data.org: официалният безплатен план включва забавени резултати и токен, който не трябва да се вгражда публично в GitHub Pages.
- TheSportsDB: има безплатен публичен ключ, но лимитите на срещите са силно орязани; безплатните условия забраняват публикуване в app store без платен абонамент. Това е непрактично за планиран бъдещ APK.
- SportScore също не гарантира точност или покритие. Първо трябва да бъде изпробван на реалния Android с конкретни срещи.
