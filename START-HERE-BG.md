# MyHub v2.4.0 — Обновяване от Android телефон

Това е обновление **от v2.3.0 към v2.4.0**. Не се изискват компютър, Android Studio, платени услуги или нов GitHub repository.

## 1. Защити данните преди обновяване

1. Отвори досегашния MyHub.
2. Влез в **Settings → JSON Backup**.
3. Изтегли архива и провери в Android **Files → Downloads**, че действително има `.json` файл. Ако липсва, не започвай обновяване.
4. Не деинсталирай приложението и **не изчиствай данните на Chrome**. Данните са локални на телефона.

## 2. Качи актуализираните файлове през GitHub

1. Изтегли `MyHub-v2.4.0-UPDATE-ONLY.zip` от този разговор и го разархивирай чрез **Files** на Android.
2. Отвори GitHub в Chrome. При нужда включи **Desktop site** от менюто на браузъра.
3. Отвори **същия repository**, който използва сегашният MyHub v2.3.0.
4. В ZIP има файл **`CHANGED-FILES.txt`**. Той изброява точно кои файлове трябва да бъдат качени или заменени. Качвай всеки в правилната папка, например `js/football.js` в `js` и `football.css` в корена на repository-то.
5. За съществуващ файл можеш да отвориш файла в GitHub, да натиснеш молива **Edit**, да изтриеш старото съдържание и да поставиш **целия** код от едноименния файл в разархивирания ZIP. После избери **Commit changes**. За новите файлове използвай **Add file → Create new file** или **Upload files** в подходящата папка.
6. Не качвай ZIP като един файл в repository-то: GitHub Pages не го разархивира автоматично. Не създавай допълнителна папка `MyHub-v2.4.0` вътре в repository-то.
7. Остави GitHub Pages да публикува commit-а. Ако вече използваш Pages от `main` / `root`, не променяй настройките.

## 3. Активирай новата PWA версия

1. Отвори MyHub **от съществуващата икона** на телефона.
2. Отиди в **Settings → PWA и обновления** и натисни бутона за проверка. Ако има чакащо обновление, активирай го оттам.
3. Провери **Settings → Version 2.4.0**. Ако още пише 2.3.0, затвори приложението и го отвори отново, след като GitHub Pages публикува файловете. Не изчиствай Site Data.

## 4. Провери Football с мач от събота или неделя

1. Отвори **Футболни резултати**, избери същото първенство, в което преди е имало забавени резултати.
2. Натисни **Обнови**. Ако се появи ограничение за заявки, изчакай позволения интервал.
3. При минал мач без потвърден резултат ще видиш **„Няма потвърден краен резултат от източника“**.
4. Избери **„Провери този мач“**. MyHub ще провери директно конкретния мач в OpenLigaDB, като запазва старите резултати. Ако и след проверката няма финален резултат, значи приложението не може да го получи от този източник.
5. При нужда натисни **„Потърси резултата в браузъра“** — отваря се външно търсене само след твое действие. Това не променя запазените резултати.
6. Провери също Notes, Weather, Calendar и останалите лични данни — те трябва да бъдат запазени.

**Важно:** OpenLigaDB няма гаранция за точни или навременни резултати. „Непотвърден“ не означава със сигурност, че срещата е изиграна — тя може да е била отложена. MyHub не попълва предполагаеми резултати.

## 5. При проблем

- Ако PWA не се обнови, провери в GitHub дали всички файлове от `CHANGED-FILES.txt` са качени на правилните места, и дали Pages е публикувал последния commit.
- Ако футболът продължава да няма резултати, кажи **кое първенство** и **кои два отбора**, за да проверим дали OpenLigaDB поддържа и обновява конкретното състезание.
- Ако Notes или други локални данни не се виждат, **не натискай Restore веднага**. Първо провери дали си отворил същата PWA/URL и дали Chrome не използва друг профил. Restore замества текущите локални данни.

## Защо тази версия е малка

Вместо да добавя нови инструменти, v2.4.0 поправя конкретния проблем във Football, запазва съществуващата IndexedDB `myhub-local` версия 1 и JSON Backup формат 1, и не изисква външна регистрация или платен API.
