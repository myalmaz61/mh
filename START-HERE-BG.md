# MyHub v0.4.0 — обновяване от Android с GitHub

Това е продължение на работещата **v0.3.0**, не нов проект. Новият инструмент е **Календар** с месечен и дневен изглед, събития и повторения. Няма нужда от компютър, Android Studio, Google Calendar или платени услуги.

## 1. Запази данните си ПРЕДИ обновяването

1. Отвори инсталирания MyHub v0.3.0 на телефона, от **същия адрес**, който вече използваш.
2. Влез в **Настройки → Изтегли JSON архив**.
3. В Android **Files / Downloads** провери дали действително съществува файл `MyHub-backup-YYYY-MM-DD.json`.
4. Пази този личен архив само на сигурно място. **Не го качвай в GitHub** — публичният репозиториум може да се чете от всеки.
5. **Не деинсталирай** PWA, не използвай **Clear site data / Изчистване на данните на сайта**, не сменяй адреса на проекта.

## 2. Избери правилния ZIP

- **`MyHub-v0.4.0-UPDATE-ONLY.zip`**: препоръчителен при вече работеща v0.3.0; съдържа само новите и пълните променени файлове.
- **`MyHub-v0.4.0.zip`**: пълният проект, за създаване на ново хранилище или пълна проверка.
- **`MyHub-v0.4.0-FULL-SOURCE.md`**: целият текст на всеки нов или променен **текстов файл**, ако предпочиташ Copy → Paste вместо Upload.

Разархивирай ZIP чрез приложението **Files** на Android. **Не качвай ZIP като един файл** в GitHub Pages — файловете вътре трябва да са по правилните папки.

## 3. Замени само тези файлове в GitHub

Отвори **същия GitHub репозиториум** като досега, например `https://github.com/ТВОЯТ-ПРОФИЛ/myhub`. В Chrome можеш да включиш **⋮ → Desktop site**, за да се виждат бутоните за файлове.

**В основната папка на проекта (до index.html):**

- `index.html` — замени
- `calendar.css` — **нов файл**
- `sw.js` — замени
- `package.json` — замени
- `README.md` — замени
- `START-HERE-BG.md` — замени

**В папка `js`:**

- `app.js` — замени
- `config.js` — замени
- `db.js` — замени
- `i18n.js` — замени
- `calendar.js` — **нов файл**
- `calendar-core.js` — **нов файл**

**В папка `tests`:**

- `calendar.test.mjs` — **нов файл**
- `timer.test.mjs` — замени (проверката очаква v0.4.0)
- `weather.test.mjs` — замени (проверката очаква кеш v0.4.0)

Това са **15 файла** — всеки файл в архива е **цял**, не отделни редове за ръчно поправяне. Останалите файлове (`styles.css`, `timer.css`, `weather.css`, съществуващите JS инструменти, `manifest.webmanifest`, иконите и `.nojekyll`) **остават непроменени**.

### Как става качването от телефона

1. В GitHub отвори необходимата папка, например корена, `js` или `tests`.
2. Натисни **Add file → Upload files** и избери файловете от съответната папка на разархивирания ZIP.
3. Ако GitHub поиска потвърждение, избери **Commit changes** в основния branch (`main`).
4. Ако GitHub не позволи заменяне на файл с Upload: отвори файла → **Edit** (молив) → **Select all** → постави **пълния** код на файла от `MyHub-v0.4.0-FULL-SOURCE.md` → **Commit changes**.
5. За нов файл използвай **Add file → Create new file**, въведи точно името му, постави целия код и натисни **Commit**.
6. Качи **всички 15 файла**, преди да започнеш да проверяваш новата версия на сайта.

Важни точни пътища: `calendar.css` трябва да е **до `index.html`**, `calendar.js` и `calendar-core.js` трябва да са **в `js/`**, а `calendar.test.mjs` — в **`tests/`**. **Не** поставяй всичко под допълнителна папка `MyHub-v0.4.0/`.

## 4. Проверка на обновяването

1. Провери **GitHub → Actions** или **Settings → Pages**, че публикуването на GitHub Pages е минало успешно.
2. Отвори **същия GitHub Pages URL** както досега, например `https://ТВОЯТ-ПРОФИЛ.github.io/myhub/`.
3. Отвори **Настройки → Версия**, трябва да показва **v0.4.0**.
4. Ако се вижда старият номер, първо обнови страницата в Chrome. Ако приложението покаже **„Налична е нова версия“**, натисни **„Обнови“**. Затвори и отвори отново PWA, ако е необходимо. **Не изтривай site data**.
5. Отвори **Инструменти → Календар**. Календарът не се добавя автоматично към любимите на началния екран — ако го искаш там, отвори **Настройки → Любими инструменти → Календар**.

## 5. Бързи проверки на телефона

- **Събитие:** избери дата, натисни **„Ново събитие“**, напиши заглавие, дата и евентуален час и бележка → **„Запази събитието“**. Трябва да се появи за съответния ден.
- **Дневен изглед:** натисни **„Ден“**, после стрелките **‹ / ›**. Връщането към **„Месец“** трябва да работи.
- **Повторение:** създай седмично събитие за петък; провери дали се вижда и следващия петък.
- **Редакция:** отвори събитие → **✎**, смени заглавието и запази. При повтарящи се събития редакцията променя **цялата поредица**.
- **Изтриване:** отвори събитие → **✎ → Изтрий**; появява се потвърждение.
- **Запазване:** затвори и отвори MyHub отново. Събитието трябва да остане.
- **Архив:** изтегли нов JSON архив. Вътре има поле `calendarData`. Той включва събитията. **Не използвай Restore само за тест**, без да имаш отделно резервно копие, защото Restore замества данните.
- **Старите инструменти:** отвори Notes, Timer, Weather, Calculator; провери дали всичко съществува и работи както преди.
- **Офлайн:** след като веднъж отвориш новата версия онлайн, включи самолетен режим и пробвай Календар + Бележки.

## 6. Важно за повторенията и старите архиви

- Месечно събитие на **31 януари** няма да се премести на 28 февруари — февруари се **пропуска**. На 31 март събитието отново се появява.
- Годишно събитие на **29 февруари** ще се показва само във високосни години.
- Календарът не синхронизира Google Calendar, не изпраща известия и **не е системна аларма**. Записва датата и незадължителен час според твоето локално време.
- Архивите от **v0.1.0, v0.2.0 и v0.3.0** остават съвместими с v0.4.0. Но ако **възстановиш стар архив**, който няма `calendarData`, текущите събития в календара ще се изчистят. Затова направи **нов архив от v0.4.0**, преди да възстановяваш каквото и да било.
- Всички данни остават локални в Chrome/инсталираната PWA. GitHub държи само програмните файлове, не твоите лични събития.

## 7. Ако не се вижда Calendar или v0.4.0

- Увери се, че **всички файлове** от UPDATE-ONLY са качени в **точните папки**.
- Ако липсва `calendar.css`, `js/calendar.js` или `js/calendar-core.js`, Service Worker няма да успее да кешира новия пакет.
- Провери в GitHub Pages дали последният deployment е успешен.
- Отвори Pages адреса в Chrome и обнови страницата, преди да отваряш инсталираната PWA.
- Не отстранявай проблем с изчистване на локалното хранилище — това може да изтрие бележките и събитията.
