# MyHub v2.0.0 — инструкции за Android и GitHub

Това е **обновление от v1.9.0**, а не ново приложение. Не деинсталирай текущата PWA и не изтривай данните на Chrome.

## 1. Защити данните си

1. Отвори MyHub v1.9.0 → **Settings / Настройки** → **JSON Backup / Експорт**.
2. Запази файла. С приложението Files провери, че `MyHub-backup-....json` действително присъства в **Downloads** и не е 0 байта.
3. **Не качвай личния JSON файл в публичното GitHub хранилище.** Пази го на телефона или на друг носител по твой избор.

## 2. Кой ZIP да използваш

- Ако вече си публикувал v1.9.0, изтегли `MyHub-v2.0.0-UPDATE-ONLY.zip`.
- Ако започваш от ново хранилище, изтегли `MyHub-v2.0.0.zip`.
- Разархивирай файла с **Files** на Android. Остави файловете в същите папки и с точно същите имена.
- В `CHANGED-FILES.txt` е точният списък на това, което се добавя или замества. Пълен текст на всеки променен файл има в отделния `FULL-SOURCE.md`.

## 3. Качване през GitHub от Android

1. В Chrome отвори **съществуващото** GitHub хранилище на MyHub. Ако е нужно, включи **Desktop site** от менюто на Chrome.
2. Отвори всяка от папките, посочени в `CHANGED-FILES.txt` — например `js` или `tests`.
3. Използвай **Add file → Upload files** и избери съответните нови/променени файлове от разархивираната папка. При качване с познатото име GitHub трябва да покаже, че файлът се заменя. Потвърди **Commit changes**.
4. За файловете в основната папка (`sw.js`, `package.json`, `README.md` и др.) се върни в основата на репозитория и ги качи там.
5. При нова папка можеш да я създадеш през **Add file → Create new file**, като напишеш `ИМЕ-НА-ПАПКА/temporary.txt` и я използваш за качването на останалите файлове. Не променяй съществуващи лични JSON данни в GitHub — те не трябва да са там.
6. Не премахвай старите `js`, CSS или файловете от останалите инструменти. ZIP-ът за обновление **не** е целият проект.
7. В **Settings → Pages** провери, че все още е избрано `Deploy from a branch`, `main`, `/ (root)`.

Ако GitHub позволява избор на няколко файла от една папка, качи ги заедно. Ако мобилният браузър не предлага папки, използвай `FULL-SOURCE.md`, отвори съответния файл в GitHub и **замени цялото му съдържание**, без редакции на отделни редове.

## 4. Обновяване на инсталираната PWA

1. Отвори MyHub от **съществуващата икона** на Android.
2. Отвори **Settings → PWA и обновления** и избери **Провери за обновление**.
3. Ако има банер за нова версия, натисни **Обнови**. Ако още се показва старата версия, затвори и отвори приложението отново след публикуването.
4. Провери **Settings → Version 2.0.0**. Ако продължава да показва 1.9.0, провери GitHub Pages deployment и активния Service Worker — **не изчиствай данните на сайта** като първа стъпка.

## 5. Тестове на реалния Android

- Виж дали Notes, Tasks и Calendar запазват старите записи.
- Създай нова тестова бележка, затвори и отвори приложението, провери дали е останала.
- Отвори Calculator, World Clock, Weather и Football (онлайн за последните две).
- Включи Airplane mode, отвори отново PWA и пробвай Notes, Calculator и Calendar. Мрежовите модули могат да покажат само кеширани данни.
- От Settings създай **нов JSON Backup**. Провери файла в Downloads. 
- В Restore избери файл, виж обобщението и натисни **Отказ**. **Не потвърждавай замяна на реалните данни само за тест.**
- В Settings провери PWA & Updates и Data Health. Не се тревожи, ако статусът на онлайн услугите не е достъпен в самолетен режим.

## 6. Ако има проблем

- Увери се, че всички файлове от `CHANGED-FILES.txt` са качени в **правилните папки**, а не в една обща.
- Провери дали GitHub Pages е публикувал последния commit.
- Ако има проблем само с Weather, Football или RSS, може да е външна услуга — не означава загуба на локални данни.
- Ако ти се наложи да възстановяваш истински JSON архив, първо провери какво ще бъде заменено. Ако други записи са променени, MyHub може да поиска отново да избереш файла.
- Не използвай „Clear storage“ и не деинсталирай PWA, преди да имаш проверен архив.

## 7. Бъдещ APK

Виж `APK-READINESS-BG.md`. **v2.0.0 не включва APK**, не изисква Android Studio и не променя местоположението на данните. За бъдещ APK ще направим прехвърляне чрез JSON Export/Import.
