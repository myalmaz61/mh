# MyHub v1.9.0 — Инструкции за Android и GitHub

## 1. Преди да качваш

1. Отвори сегашния MyHub **v1.8.0** от съществуващата PWA икона.
2. В **Настройки / Settings → JSON Backup** създай нов архив.
3. С Android Files отвори **Downloads** и провери, че JSON файлът действително е изтеглен, не е 0 KB и може да се отвори като текст. Ако можеш, направи отделно второ копие.
4. **Не деинсталирай MyHub**, не изтривай **Chrome Site Data/Storage/IndexedDB** и не създавай нов GitHub Pages адрес за съществуващата инсталация.

## 2. Обновяване от v1.8.0 на v1.9.0

1. Изтегли **`MyHub-v1.9.0-UPDATE-ONLY.zip`** от разговора и го разархивирай на телефона.
2. Вътре отвори `CHANGED-FILES.txt`. Това е **точният списък** с файловете, които трябва да качиш.
3. В Chrome отвори **същото GitHub repository** на MyHub. При нужда използвай меню **⋮ → Desktop site**, за да видиш удобните GitHub контроли.
4. Качи кореновите файлове в корена, `js/...` в папка `js`, `tests/...` в папка `tests`. При съществуващ файл замени **цялото съдържание** със съответния нов файл. Не е необходимо да докосваш неизброените файлове.
5. Използвай **Commit changes**. **Не качвай ZIP-а като един файл** вместо да качиш съдържанието му.
6. Отвори MyHub от **съществуващата PWA икона**. Провери **Настройки → Version 1.9.0**. Ако виждаш v1.8.0, отвори с интернет и използвай **Settings → PWA и обновления → Проверка за обновление**; ако се появи бутон **Обнови**, натисни го. Не изчиствай кеша ръчно с изтриване на личните данни.

Ако тепърва създаваш проекта, използвай **`MyHub-v1.9.0.zip`** с всички файлове; GitHub Pages: Settings → Pages → Deploy from a branch → `main` / `(root)`.

## 3. Проверка на телефона — безопасен тест

1. От Начало натисни **+ → Събитие**. Въведи пробно заглавие **Тест MyHub**, дата утре и час **14:30**. Избери **Без повторение** и натисни **Запази**.
2. MyHub трябва да отвори Calendar с новото събитие. Провери дали е запазена точната дата/час.
3. В дневния изглед натисни **⧉ Дублирай** до тестовото събитие. Трябва да се появи предварително попълнен формуляр, без събитието още да е копирано. Избери друга дата и натисни **Запази събитието**.
4. Провери, че и двете събития съществуват, всяко с правилната си дата. След теста можеш да ги изтриеш от Calendar.
5. Опитай **+ → Събитие** с ежеседмично повторение и провери бъдещата седмица в Calendar. За теста е достатъчна една пробна поредица.
6. Провери **Notes, Tasks, Bookmarks**, любимите инструменти, настройките и старите събития. Нищо старо не трябва да липсва.
7. Включи самолетен режим **след** първото успешно онлайн зареждане на v1.9.0 и провери Quick Add → Събитие и Calendar. И двете трябва да работят локално.

**Няма системни аларми:** датата и часът в Calendar са за информация; PWA не обещава известия при заключен телефон.

## 4. Ако нещо не е наред

- **Нова версия не се появява:** провери `sw.js`, `js/config.js`, `js/quick-add.js` и че GitHub Pages е публикувал текущия commit; използвай бутона за проверка на обновления. Не преинсталирай.
- **Quick Add казва „Данните са повредени“:** не изтривай или възстановявай автоматично. Направи копие на съществуващото състояние, ако е възможно, и сподели текста на грешката.
- **Грешна дата:** провери часовата зона и датата на Android, както и избора в полето `Дата`. Датите се съхраняват като `YYYY-MM-DD` без автоматично изместване от timezone.
- **Restore:** заменя всички локални данни, не обединява. Не възстановявай стар архив само за тест — използвай преглед и натисни **Отказ**.

MyHub v1.9.0 остава напълно безплатна PWA с локални данни, работеща без компютър и Android Studio.
