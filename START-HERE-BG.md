# MyHub v0.9.0 — Android + GitHub (само телефон)

Тази версия е **обновяване от v0.8.0**, не ново приложение. Не трябва да създаваш нов GitHub repository, да изтриваш данни или да инсталираш Android Studio.

## 1. Резервно копие преди всичко

1. Отвори инсталирания MyHub v0.8.0.
2. От **Настройки → Архивиране и възстановяване** изтегли JSON Backup.
3. Провери през Files / Downloads дали JSON файлът наистина е наличен. По желание направи и второ копие на безопасно място.
4. **Не деинсталирай PWA**, не изчиствай данните на Chrome и не сменяй сайта или GitHub Pages адреса.

## 2. Кой архив да използваш

- Ако вече имаш **v0.8.0**, използвай `MyHub-v0.9.0-UPDATE-ONLY.zip` — включва само добавените/променените файлове.
- Ако създаваш съвсем нов проект, използвай `MyHub-v0.9.0.zip` — пълната версия.
- `MyHub-v0.9.0-FULL-SOURCE.md` съдържа **пълния текст на всеки нов или променен текстов файл**, ако трябва да работиш чрез Copy/Paste в GitHub.

## 3. Качване от Chrome на Android

1. Изтегли и разархивирай `MyHub-v0.9.0-UPDATE-ONLY.zip` с приложението Files.
2. Отвори `github.com` в Chrome и съществуващото хранилище на MyHub.
3. Ако мобилният интерфейс скрива функциите, в Chrome избери **⋮ → Desktop site**.
4. В **основната папка** (където се намира текущият `index.html`) качи чрез **Add file → Upload files** файловете от корена на архива: `index.html`, `sw.js`, `today.css`, `package.json`, `README.md`, `START-HERE-BG.md`.
5. Отвори папката **`js`** в GitHub и качи: `app.js`, `config.js`, `i18n.js`, `today.js`, `today-core.js`, `diagnostics.js`, `diagnostics-core.js`.
6. Отвори папката **`tests`** и качи всички файлове от тази папка в архива. Те са проверки, а не част от интерфейса.
7. Запази промените с **Commit changes**. Старите модули (`notes.js`, `weather.js`, `football.js`, `rss.js`, `calculator.js` и т.н.), папката `icons`, старите CSS файлове и `manifest.webmanifest` не се изтриват или заменят.

**Ако GitHub не позволява да замениш съществуващ файл:** отвори файла → **Edit** (молив) → избери целия стар текст → постави целия нов текст от `MyHub-v0.9.0-FULL-SOURCE.md` → Commit. Не редактирай отделни редове. За новите файлове използвай **Add file → Create new file** и пълното им съдържание.

**Не качвай ZIP като един файл в GitHub** и не поставяй цялата папка `MyHub-v0.9.0` вътре в корена: GitHub Pages трябва да вижда `index.html` на същото място като преди. **Не променяй GitHub Pages настройките**.

## 4. Проверка на телефона

1. Отвори съществуващата икона на MyHub. Ако има **„Налична е нова версия“**, използвай **„Обнови“**, след което отвори приложението отново. В **Настройки** трябва да пише **v0.9.0**.
2. Увери се, че старите Notes, Tasks, Calendar, Football, RSS и Bookmarks са на мястото си.
3. Създай **нова задача със срок днес** в Tasks и **събитие днес** в Calendar. Върни се в Начало: трябва да се появи компактно поле **„Днес“**, с броя задачи и събития.
4. Натисни **„Покажи подробности“**: трябва да се видят заглавията, без да се отварят други екрани. Натисни **„Отвори задачите“** или **„Отвори календара“**.
5. Отбележи задачата като изпълнена и изтрий тестовото събитие. При връщане в Начало, когато вече няма задачи/събития със срок, полето „Днес“ трябва да изчезне.
6. Отвори **Настройки → Състояние на данните**. Виж броя записи, статуса на съхранението и мястото според браузъра. Числата са приблизителни за мястото и могат да включват други сайтове със същия `github.io` origin.
7. Изтегли нов JSON Backup и **провери в Downloads дали реалният файл е създаден**. Датата в „Състояние на данните“ означава, че экспортът е започнат, не че Android гарантирано е запазил файла.
8. Пусни **самолетен режим** и отвори MyHub от иконата. „Днес“ и локалните инструменти трябва да се показват с наличните локални данни; външните прогнози, футболни API и RSS може да не се обновяват.

## 5. Защита на данните

- `myhub-local` остава **IndexedDB version 1**: няма промяна или изтриване на базата при обновяване.
- „Днес“ **само чете** записите от Tasks и Calendar, не ги променя.
- Диагностиката **само проверява** данните. При повреден запис показва грешка, вместо да го замени.
- Датата на последния подготвен JSON архив е допълнителен метаданен запис (`lastBackupExportAt`). Не е част от задължителния JSON формат и не е потвърждение за успешно изтегляне.
- Възстановяването от JSON **замества всички текущи данни**. Ако възстановиш стар архив отпреди даден модул, данните в новия модул ще бъдат празни. Запази текущ JSON Backup преди Restore.
- Не използвай изчистване на кеша/данните като първа стъпка при стар екран. Ако виждаш v0.8.0, провери GitHub Pages публикуването, `sw.js`, наличното известие за обновяване и презареждането от иконата.
- При бъдещ Capacitor APK данните от PWA няма да се преместят автоматично: Export JSON от PWA → Import JSON в APK.

## 6. Какво е тествано

- **92 от 92 Node автоматизирани теста успешни**, включително тестовете на старите версии и новите функции.
- Новите панели „Днес“ и „Състояние на данните“ са проверени в изолирана Chromium среда с тестови данни и мобилен размер на екрана.
- Пълен тест на реално инсталирана PWA в Android Chrome не е извършен; тестовият Chromium в работната среда блокира отварянето на локалния HTTP адрес. Затова провери стъпките по-горе, преди да разчиташ на версията за важни ежедневни записи.

## 7. Какво следва

Препоръка: **v1.0** да обедини глобално търсене за бележки, задачи, календар и връзки, без да претрупва началния екран. **Quick Add** може да се добави след това. Бъдещият APK през GitHub Actions остава отделна фаза, когато PWA е потвърдена като стабилна.
