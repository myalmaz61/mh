# MyHub v0.3.0 — обновяване само с Android телефон и GitHub

Това е **надграждане на работещата v0.2.0**. Включва Таймер и Хронометър, без да променя базата данни и без платени услуги. Не ти трябва компютър, Android Studio или API ключ.

## 1. ПЪРВО направи резервно копие

1. Отвори съществуващата PWA **MyHub v0.2.0**.
2. Влез в **Настройки → Изтегли JSON архив**.
3. Отвори **Files / Изтегляния** на телефона и се увери, че `MyHub-backup-...json` съществува. Пази го извън папката на GitHub проекта, защото съдържа лични бележки.
4. **Не деинсталирай PWA и не използвай „Clear site data“ / „Изчистване на данните“.** Данните са локални в Chrome на същия адрес, а не в GitHub.

## 2. Кой ZIP да изтеглиш

- `MyHub-v0.3.0-UPDATE-ONLY.zip` — препоръчителен, **само създадените и променените файлове** за надграждане от v0.2.0. Всички файлове са пълни, а не отделни поправки на редове.
- `MyHub-v0.3.0.zip` — **всички файлове**, ако създаваш ново GitHub хранилище или искаш цял проект.
- `MyHub-v0.3.0-FULL-SOURCE.md` — пълният текст на всеки нов или променен текстов файл, ако редактираш през GitHub с Copy/Paste.

Изтегли и разархивирай ZIP чрез **Files by Google / Files / My Files** на Android. ZIP **не** се качва като един файл в GitHub Pages — съдържанието му трябва да попадне на правилните места.

## 3. Качване в СЪЩОТО GitHub хранилище

1. Отвори GitHub в Chrome на Android и влез в същия репозиториум, от който работи v0.2.0. Например `https://github.com/ТВОЕТО-ИМЕ/myhub`.
2. При нужда включи **Chrome ⋮ → Desktop site**.
3. В **основната папка** на хранилището (там, където е `index.html`) качи/замени:
   - `index.html`
   - `timer.css` (**нов**)
   - `sw.js`
   - `package.json`
   - `README.md`
   - `START-HERE-BG.md`
4. Отвори папката **js** в GitHub и качи/замени:
   - `app.js`
   - `config.js`
   - `db.js`
   - `i18n.js`
   - `timer.js` (**нов**)
   - `timer-core.js` (**нов**)
5. Отвори папката **tests** и качи/замени:
   - `smoke.test.mjs`
   - `weather.test.mjs`
   - `timer.test.mjs` (**нов**)
6. За качване можеш да използваш **Add file → Upload files → Commit changes**, ако GitHub позволява качване на съществуващите имена. Ако не ги замени: отвори съответния файл → **Edit (молив)** → **Select all** → постави **целия** текст от `MyHub-v0.3.0-FULL-SOURCE.md` → **Commit changes**. За нови файлове използвай Add file → Create new file или Upload files.
7. Увери се, че `timer.css` е **до** `index.html`, а `timer.js` и `timer-core.js` са **в папка js**. Не оставяй ненужна външна папка `MyHub-v0.3.0` в GitHub.
8. Остави всички останали файлове от v0.2.0 без промяна — особено `styles.css`, `weather.css`, `manifest.webmanifest`, бележките и другите JS модули, иконите и `.nojekyll`.

**Съвет:** Ако качваш файловете на няколко пъти, довърши всички Commit операции, преди да отвориш PWA за обновяване. Service Worker трябва да получи всички нови файлове заедно.

## 4. Провери обновлението

1. Използвай **същия адрес** на GitHub Pages както за v0.2.0.
2. В MyHub отвори **Настройки → Версия**; трябва да е **v0.3.0**.
3. Ако се появи **„Налична е нова версия → Обнови“**, натисни го. Ако още е v0.2.0, отвори сайта в Chrome, обнови го и рестартирай инсталираната PWA. **Не изчиствай данните на сайта.**
4. Влез в **Инструменти → Таймер и хронометър**.
5. За да го виждаш директно на началния екран: **Настройки → Любими инструменти → Таймер и хронометър**. По подразбиране не е добавен, за да остане началният екран опростен.

## 5. Проверки на телефона (около 3–5 минути)

- **Таймер:** избери 0 часа, 0 минути, 5 секунди → Старт. Остави екрана отворен и видим: трябва да приключи и да покаже `Приключил`. При позволен звук от Chrome може да чуеш кратко пиукане.
- **Пауза:** избери 20 секунди, Старт → Пауза → Продължи. Оставащото време не бива да се рестартира от нулата.
- **Връщане:** пусни 30 секунди, отиди в друг инструмент или минимизирай PWA, върни се след известно време. Показаното време трябва да е коригирано по действително изминалите секунди. **Не очаквай звукова аларма във фонов режим.**
- **Запазена продължителност:** въведи 3 минути, дай име `Чай`, натисни `Запази`. Избери новия бутон и провери стойността.
- **Хронометър:** Старт → Обиколка → Пауза → Продължи. Провери междинните времена. Натисни Нулирай, когато искаш да изтриеш текущите обиколки.
- **Архив:** отвори Settings → JSON Backup. Новият JSON трябва да съдържа и поле `timerData`. Старите архиви v0.1/v0.2 остават съвместими, но **възстановяването заменя текущите данни**; не възстановявай само за тест, ако няма нужда.
- **Проверка на стари функции:** отвори запазена бележка, Calculator и Weather. Провери дали данните са останали.
- **Офлайн:** включи Airplane mode и пробвай Timer, Stopwatch, Notes и Calculator след като приложението е заредено веднъж онлайн.

## 6. Ограничение на Android PWA

Android Chrome може да ограничава JavaScript, когато PWA е скрита, затворена или телефонът е заключен. Таймерът пази абсолютния си краен час, а хронометърът — реалното начално време, затова при връщане показанията се преизчисляват. **Няма гарантирана системна аларма или фонов звук.** Звуковият сигнал е опционален само при видим екран на таймера. За печене, важни напомняния и други ситуации, при които трябва да чуеш алармата при заключен телефон, използвай системното Android Clock приложение.

При JSON Export работещите таймери и хронометри се записват **паузирани в архива**, без това да паузира истинските броячи. Това предпазва от неочаквано „доизтичане“ при възстановяване на стар архив.

## 7. Какво да провериш, ако не се обнови

- GitHub **Actions / Pages deployments**: провери дали има успешно публикуване (при GitHub Pages публикуването може да отнеме малко време).
- Адресът и хранилището трябва да са **същите** — не премествай приложението на нов домейн, ако искаш да запазиш локалните данни.
- `js/timer.js`, `js/timer-core.js` и `timer.css` трябва да съществуват. Ако един липсва, Service Worker няма да може да кешира новата версия.
- Не качвай файловете като вложени в допълнителна папка; провери дали GitHub показва правилните им пътища.
- Не изтривай локалното хранилище като първа стъпка за отстраняване на проблем.

Следващият планиран модул е **Calendar v0.4.0**, след като провериш, че v0.3.0 работи на телефона.
