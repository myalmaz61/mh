# MyHub v2.8.0 — инструкции за Android и GitHub

Този проект е за **Android телефон + Chrome + GitHub Pages**. Не изисква компютър, Android Studio или платена услуга.

## 1. Направи безопасен архив

1. Отвори текущата **MyHub v2.7.0** от съществуващата икона.
2. Влез в **Settings → JSON Backup** и изтегли архива.
3. Отвори папката **Downloads** на телефона и провери, че JSON файлът действително е записан. Не изтривай предишните архиви.
4. Не деинсталирай PWA и не използвай `Clear site data` в Chrome — това може да изтрие локалните бележки и настройки.

## 2. Качи обновлението, без да изтриваш стария проект

1. Изтегли `MyHub-v2.8.0-UPDATE-ONLY.zip` и го разархивирай през Files на Android.
2. Отвори **същото GitHub хранилище**, което в момента обслужва MyHub. Можеш да включиш **Desktop site** в Chrome, ако мобилните бутони са ограничени.
3. В разархивираната папка отвори `CHANGED-FILES.txt`. Там е точният списък на **пълните** нови и променени файлове.
4. За файл, който вече съществува, отвори го в GitHub и избери **Edit**; замени **цялото** старо съдържание с новия пълен файл, след което **Commit changes**. Където GitHub позволява, можеш да използваш **Add file → Upload files** за няколко файла в конкретната папка.
5. За новите файлове създай пътя точно както е в архива, например `js/notes-view-core.js`, `tests/notes-view.test.mjs` и `tests/weather-outlook.test.mjs`.
6. **Не качвай ZIP файла като един файл в GitHub и не създавай допълнителна директория `MyHub-v2.8.0` в корена**: GitHub Pages трябва да вижда `index.html`, `js/`, `styles.css` и останалите файлове на същите места като преди.
7. Не изтривай файловете, които не присъстват в списъка. Специално **не променяй файловете `js/football*.js`** — поправката от v2.7.0 се запазва.
8. След като GitHub Pages публикува последния commit, отвори инсталирания MyHub → **Settings → PWA и обновления** и провери за нова версия. Активирай я, ако се появи предложение.
9. Провери дали **Version** показва `2.8.0`.

> Ако по време на качването част от файловете са обновени, а други още не, възможно е временно да видиш стар интерфейс или грешки. Довърши всички файлове, преди да тестваш.

## 3. Проверка на Notes

1. Отвори Notes. Провери дали виждаш двата компактни избора **Показвай** и **Сортиране**.
2. Създай тестова бележка, маркирай я като **Любима**, върни се към списъка и избери **Любими**.
3. Пробвай **Закрепени**, търсене по заглавие и по текст от checklist и сортиране **По заглавие**.
4. Отвори тестова бележка и използвай **Сподели**. Ако Android предложи други приложения, можеш да отмениш споделянето. Ако браузърът няма Share API, MyHub ще опита да копира текста.
5. Провери, че старите ти бележки не са изчезнали. Филтърът **Всички** показва всички, които отговарят на текущото търсене.

## 4. Проверка на Weather

1. Отвори Weather и избери съществуващ град (например Newport, Shropshire).
2. Обнови прогнозата при наличен интернет.
3. В панела с вероятност за дъжд виж дали има час с **поне 50% шанс за валежи** в следващите налични 12 часа.
4. Имай предвид: часът е **местен за избрания град**, а процентът **не е обещание за дъжд**.
5. Изключи интернет и отвори Weather отново. Последно запазената прогноза трябва да се показва с указание, че е кеширана или остаряла.

## 5. Проверка на останалите инструменти

Отвори Football → SportScore → English Premier League и потвърди, че се държи както във v2.7.0. След това провери дали Tasks, Calendar и JSON Backup са достъпни и дали старите записи са налични. **Не използвай Restore само за тест върху истинските данни**; можеш да отвориш архива за преглед и да отмениш.

## Важно

- Архивите пазят данните на телефона, а файловете в GitHub са **само код**. Качването на кода не качва частните ти бележки.
- Двата ZIP архива са: `MyHub-v2.8.0-UPDATE-ONLY.zip` (за обновяване от v2.7.0) и `MyHub-v2.8.0.zip` (пълният проект).
- Не са необходими нови разрешения, акаунти или платени API.
