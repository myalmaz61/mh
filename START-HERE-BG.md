# MyHub v0.7.0 – Инструкции за Android + GitHub

**Продължаваме от работещата v0.6.0.** Нищо не започваме от нулата. Новият инструмент е **RSS Reader**.

## 1. Преди обновяването

1. Отвори инсталирания MyHub на Android.
2. Влез в **Настройки → JSON Backup → Експорт**. Запази файла в Downloads, например `MyHub-backup-2026-11-20.json`.
3. Не изтривай Chrome site data, не деинсталирай старата PWA и не променяй адреса на GitHub Pages.
4. Изтегли `MyHub-v0.7.0-UPDATE-ONLY.zip` от отговора. Разархивирай с Files / Files by Google.

## 2. Как да качиш променените файлове (само телефон)

Отвори стария GitHub repository, където е MyHub. Ако мобилният изглед затруднява качването, избери **Chrome → ⋮ → Desktop site**.

**Създай/замени точно тези файлове (пълните им съдържания са в ZIP, няма редактиране по отделни редове):**

- В основната папка: `index.html`, `rss.css`, `sw.js`, `package.json`, `README.md`, `START-HERE-BG.md`, `rss-public-feeds.json`.
- В папка `js`: `app.js`, `config.js`, `db.js`, `i18n.js`, **новите** `rss.js`, `rss-core.js`.
- В папка `tests`: `calendar.test.mjs`, `football.test.mjs`, `tasks.test.mjs`, `timer.test.mjs`, `weather.test.mjs`, **нов** `rss.test.mjs`.
- Новата папка `scripts`: `rss-public-cache.py` (за бъдещ, незадължителен GitHub кеш).
- Новата папка `_optional`: `rss-pages.yml` (само пример; не се стартира автоматично).

**Важно:** `calculator.js`, `notes.js`, `weather.js`, `football.js`, `calendar.js`, `timer.js`, `tasks.js`, `quick-list.js`, техните CSS файлове и иконите остават непроменени. Не ги изтривай. Не качвай целия ZIP като един файл — GitHub Pages трябва да получи отделните файлове в правилните папки.

В GitHub използвай **Add file → Upload files** в съответната папка, избери файловете и **Commit changes**. Ако GitHub не позволява замяна при Upload, отвори самия файл → **Edit (молив)** → Select All → Paste пълния код от `MyHub-v0.7.0-FULL-SOURCE.md` → Commit changes. Не е нужен компютър или Android Studio.

**Не променяй Settings → Pages в този основен сценарий.** Изчакай публикуването по същия начин както в v0.6.0.

## 3. Провери обновяването

1. Отвори същия инсталиран MyHub и провери **Настройки → Версия v0.7.0**.
2. Ако се появи известие за PWA обновяване, избери **Обнови**. Ако се показва стара версия, затвори и отвори приложението отново след публикуването.
3. Провери дали старите бележки, задачи, календар, Weather, Football и настройки са налични.
4. Влез в **Инструменти → RSS Четец**. Новият инструмент не се добавя автоматично в любимите; можеш да го включиш от **Настройки**.

## 4. Работа с RSS Четец

1. Натисни **Добави източник**.
2. Въведи **точния HTTPS адрес на RSS/Atom файла**, а не само адреса на сайта. Например `https://example.org/feed.xml` е форматът на адреса (пример, не действителна препоръка за работещ източник).
3. Можеш да зададеш име и категория — например Technology, UK News, Bulgaria, Sport. Натисни **Запази източника**.
4. Използвай **Обнови**. Ако сайтът разрешава CORS, новите публикации ще се появят. Ако не, няма да се появят фиктивни статии; ще видиш грешка/предупреждение и старият кеш остава наличен.
5. Натисни **✓ Прочетена**, **☆ Любими**, или **□ За по-късно** до статията. Има филтри за прочетени/непрочетени, източници и категории, както и търсене.
6. Натисни **Отвори оригинала**, за да прочетеш цялата статия в браузъра.

**Offline:** Последно заредените статии остават за четене като кратки заглавия/описания; оригиналните сайтове може да изискват интернет. Всички отметки и прочетени статии се пазят на телефона.

## 5. Когато RSS е блокиран от CORS

GitHub Pages е статичен сайт. Не може да принуди друг сайт да разреши RSS заявки от браузър. Не използваме случаен безплатен proxy и не обещаваме автоматично обновяване на всеки RSS източник.

**Решение без сървър:**

1. Отвори RSS адреса в обикновения Chrome/Brave и изтегли XML файла (ако сайтът позволява сваляне).
2. В MyHub отиди в RSS Reader. Във филтъра над статиите избери **точния източник**, към който се отнася XML файлът.
3. Натисни **Импорт XML файл** и избери файла от Downloads.
4. Статиите ще се запазят локално. Нов XML файл се импортирa отново при нужда.

**OPML:** **Експорт OPML** прави файл със списъка на източниците и категориите; **Импорт OPML** добавя новите адреси без дубликати. **OPML НЕ е резервно копие на статии и отметки.** За това използвай **Settings → JSON Backup**.

## 6. Незадължително — публичен кеш чрез GitHub Actions

Това е за потребител, който иска автоматично опресняване на **публични** RSS източници, когато CORS пречи. **Не е необходимо за първото използване на v0.7.0.** Файловете са предварително подготвени, но **нищо няма да се изпълнява**, докато не направиш следните стъпки.

1. В публичния GitHub repository отвори `rss-public-feeds.json` → Edit. Смени `"feeds": []` например с:

   ```json
   "feeds": [
     "https://example.org/feed.xml",
     "https://example.net/rss"
   ]
   ```

   Това са **само примери за формата**, не проверени живи RSS източници. JSON файлът трябва да остане валиден, със скобите `{ ... }` и останалото съдържание.

2. Отвори `_optional/rss-pages.yml`, копирай **целия** му текст. В GitHub избери **Add file → Create new file**, въведи името `.github/workflows/rss-pages.yml`, постави текста и Commit.
3. Отиди на **Settings → Pages → Build and deployment → Source → GitHub Actions**. Това **заменя досегашния метод за публикуване** (Deploy from a branch) с новия workflow; без тази промяна кешът няма да се публикува правилно. Старият адрес на MyHub остава същият.
4. Отвори **Actions → MyHub pages with public RSS cache → Run workflow**, ако бутонът е наличен. Изчакай успешна публикация в Pages.
5. В MyHub добави същите RSS адреси локално и натисни **Публичен GitHub кеш**. MyHub ще използва само кешираните източници, чиито URL-и съвпадат с локално добавените.

Workflow е планиран за 06:17 и 18:17 UTC; изпълнението не е гарантирано точно и може да бъде забавено или спряно. В публични неактивни репозитории планираните workflow могат да бъдат изключени след 60 дни без активност. Можеш да го стартираш ръчно от GitHub Actions.

**Силно важно за поверителността:** Всеки публичен RSS адрес в `rss-public-feeds.json`, както и заглавията на кешираните статии, стават публично достъпни през GitHub. **Никога не добавяй частни RSS адреси, токени, потребителски имена и пароли там.** Отметките за прочетено и „За по-късно“ остават само локално в MyHub. Никакви твои частни данни не се изпращат към GitHub автоматично.

## 7. Резервни копия и безопасност

- Новите RSS данни се пазят в същата IndexedDB `myhub-local`, версия **1**. Няма миграция или изтриване на старите данни.
- `JSON Backup` от v0.7.0 включва източници, статии, прочетени, любими и Read Later, плюс всички стари инструменти.
- Възстановяване на стар backup от v0.1–v0.6 е възможно, **но ще замени цялото текущо съдържание и ще остави RSS празен**, защото старите файлове не съдържат RSS данни. Винаги прави нов архив, преди Restore.
- Приложението не използва tracker-и, реклами, cloud акаунти или частни API ключове.
- RSS статии и страници могат да се променят или да бъдат свалени от издателите; MyHub не гарантира съдържанието им и не заобикаля лицензи или ограничения.
