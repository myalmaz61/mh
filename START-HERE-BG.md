# MyHub v1.3.0 — Обновяване през Android + GitHub

Тези инструкции са за **обновяване на съществуваща MyHub v1.2.0**, без да губиш лични данни. Използваш само Android телефон и GitHub. Не ти трябва компютър или Android Studio.

## 1. Преди обновяването — задължително

1. Отвори **MyHub v1.2.0** на телефона.
2. Влез в **Настройки → Изтегли JSON архив (Backup)**.
3. Провери в папка **Downloads** на Android, че архивът наистина съществува. Ако имаш важни данни, направи второ копие на сигурно място.
4. **Не деинсталирай PWA и не изтривай данните на Chrome.** JSON архивът е резервна защита.

## 2. Кой ZIP файл да използваш

- **`MyHub-v1.3.0-UPDATE-ONLY.zip`**: само новите и променените файлове — използвай го при обновяване на v1.2.0.
- **`MyHub-v1.3.0.zip`**: всички файлове за чисто ново хранилище/инсталация.
- **`MyHub-v1.3.0-FULL-SOURCE.md`**: пълното съдържание на всички нови/променени текстови файлове. Можеш да копираш целите файлове.

Разархивирай с приложението Files на Android. Качвай **съдържанието** на ZIP файла, без допълнителна папка `MyHub-v1.3.0` в хранилището.

## 3. Точен списък на новите или променените файлове

- **`Коренна папка`**: `README.md`, `index.html`, `mini-tools.css`, `package.json`, `sw.js`
- **`js`**: `app.js`, `config.js`, `i18n.js`, `random-core.js`, `random-generator.js`, `text-counter-core.js`, `text-counter.js`
- **`tests`**: `calendar.test.mjs`, `football.test.mjs`, `mini-tools.test.mjs`, `quick-add.test.mjs`, `rss.test.mjs`, `search.test.mjs`, `share.test.mjs`, `tasks.test.mjs`, `timer.test.mjs`, `today.test.mjs`, `utilities.test.mjs`, `weather.test.mjs`

**Важно:** файловете в останалите папки, вкл. иконите, предишните инструменти, `manifest.webmanifest`, `share.html` и личните данни, не се изтриват.

## 4. Качване от Android в GitHub

1. Отвори **github.com** през Chrome, влез в съществуващия репозиторий `myhub` (или в името, което си избрал по-рано).
2. Ако екранът е тесен, използвай Chrome **⋮ → Desktop site**.
3. В коренната папка натисни **Add file → Upload files**, избери променените файлове за тази папка и направи **Commit changes**. Ако GitHub не позволява замяна чрез Upload files, отвори съответния файл → икона с молив **Edit** → замени *цялото* съдържание с това от `FULL-SOURCE.md` → **Commit changes**.
4. Отвори папката **`js`**, качи или замени съответните файлове от списъка. Нови файлове могат да бъдат създадени с **Add file → Create new file**, с точното име и пълния код.
5. Отвори папката **`tests`** и обнови посочените тестове. Те не са нужни за самото използване, но са част от пълния проект и помагат при следващи версии.
6. **Не създавай вложена папка `js/js` или `tests/tests`.** Качи файловете в техните директории.
7. Ако GitHub Pages вече е активен (от v1.2.0), **не променяй Pages Settings**. Новите файлове се публикуват автоматично след commit.

## 5. Проверка на приложението

1. Отвори MyHub от **съществуващата** икона на началния екран.
2. Ако MyHub покаже **„Налична е нова версия“ → „Обнови“**, използвай бутона. При необходимост затвори и отвори приложението отново.
3. В **Настройки** провери, че версията е **v1.3.0**.
4. Отвори **Всички инструменти → Брояч на текст**. Въведи `Здравей свят!` и провери „Думи: 2“. Пробвай копиране и изчистване.
5. Отвори **Всички инструменти → Случаен избор**. Въведи интервал `1`–`3`, брой `3`, включи „Без повторения“. Трябва да получиш **1, 2 и 3 в произволен ред**. Пробвай и избор от два текста.
6. Включи **самолетен режим** и отвори отново инструментите. И двата трябва да работят офлайн, след като PWA е заредила новите ресурси.
7. Увери се, че твоите **Notes, Tasks, Calendar, Bookmarks, RSS, Football и настройки** са останали запазени. Проверявай и **Share to MyHub** при нужда.

**Ако версията остане стара:** отвори приложението онлайн, провери дали `sw.js`, `js/config.js` и `index.html` са публикувани с новите версии; използвай бутона за обновяване, ако се предлага. **Не изчиствай site data** и не деинсталирай PWA, за да „поправиш“ версията.

## 6. Важни ограничения

- Text Counter и Random Generator **не запазват** въведения текст, вариантите или резултатите след напускане на екрана — това е умишлена защита на личните данни.
- Криптографският генератор изисква защитен контекст (HTTPS); GitHub Pages го предоставя. Не е предназначен за хазарт или криптографски ключове.
- Тези два инструмента не използват интернет и не изискват API ключ.
- **Не възстановявай стар JSON Backup автоматично след обновяване.** Restore *заменя* текущите данни. Използвай го само ако има реална необходимост.
- В средата на разработка **141 от 141 автоматизирани теста са успешни**, както и изолиран тест на двата нови екрана в мобилен Chromium. Пълното стартиране на PWA в Android трябва да се потвърди след публикуване.
