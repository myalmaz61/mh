# MyHub v1.1.0 — Инструкции за Android + GitHub

## 1. Преди да обновиш

1. Отвори **MyHub v1.0.0** от съществуващата икона на телефона.
2. Избери **Настройки → Изтегли JSON архив**.
3. Отвори приложението **Files** на Android и **провери дали JSON файлът действително съществува в Downloads**. Показаната дата в MyHub не гарантира завършено изтегляне.
4. Не деинсталирай PWA и **не избирай Clear site data / Изчистване на данните** в Chrome.

> **Важно:** ZIP архивът съдържа само програмния код, а не личните бележки и задачи. Те остават в IndexedDB на телефона. Backup е твоята допълнителна защита.

## 2. Кой архив да използваш?

- **MyHub-v1.1.0-UPDATE-ONLY.zip** — за съществуващ проект **v1.0.0** (препоръчително).
- **MyHub-v1.1.0.zip** — целият проект, за ново хранилище или пълна проверка на кода.
- **MyHub-v1.1.0-FULL-SOURCE.md** — пълното съдържание на всеки променен текстов файл, за ръчно копиране при нужда.

Разархивирай ZIP файла от приложението Files. Папките в архива трябва да останат така, както са: например `js/quick-add.js`, а не `quick-add.js` в главната папка.

## 3. Качване през Android Chrome в GitHub

1. Отвори съществуващия си **MyHub repository** в `github.com`.
2. При нужда включи **⋮ → Desktop site** в Chrome, за да виждаш всички бутони.
3. В главната папка на хранилището замени тези файлове с **пълното** им съдържание: `index.html`, `sw.js`, `package.json`. Добави **новия** `quick-add.css`.
4. В папка `js` замени `app.js`, `config.js`, `db.js`, `i18n.js`; добави **новите** `quick-add.js` и `quick-add-core.js`.
5. В папка `tests` замени `calendar.test.mjs`, `football.test.mjs`, `rss.test.mjs`, `search.test.mjs`, `tasks.test.mjs`, `timer.test.mjs`, `today.test.mjs`, `utilities.test.mjs`, `weather.test.mjs`; добави **новия** `quick-add.test.mjs`.
6. Качи или обнови `README.md` и `START-HERE-BG.md` в главната папка (това са само инструкции, не влияят на работата на приложението).
7. Използвай **Commit changes** за запис в `main` branch.

**Как да замениш цял файл, ако GitHub не позволява upload върху съществуващ?** Отвори файла в GitHub → иконата ✎ **Edit** → избери целия стар текст → постави **пълния нов код** от `FULL-SOURCE.md` → **Commit changes**. За нов файл използвай **Add file → Create new file** и въведи точното име, включително папката (напр. `js/quick-add.js`). Не редактирай отделни редове.

Ако GitHub позволява качване на файлове през **Add file → Upload files** в съответната папка, можеш да използваш ZIP след разархивиране. За папките `js` и `tests` трябва да качиш файловете в самите папки — не във вложено второ копие на папката.

## 4. Обновяване на PWA

1. Изчакай GitHub Pages да публикува новия commit. В **Settings → Pages** можеш да провериш адреса на сайта.
2. Отвори същия URL в Chrome. **Не променяй адреса** и не инсталирай ново копие на PWA.
3. Ако се появи **Налична е нова версия → Обнови**, натисни го.
4. Ако версията не се променя веднага, затвори MyHub и го отвори отново през същата икона.
5. Отвори **Настройки** и провери **v1.1.0**.

**Не използвай Clear data / Clear storage** като начин за принудително обновяване. Това може да изтрие личните данни.

## 5. Как да провериш новото

1. На **Начало** има малък плаващ бутон **+** долу вдясно, над навигацията.
2. Натисни **+ → Задача**. Въведи `Купи мляко`, по желание избери срок и **Важна задача**, после **Запази**.
3. Трябва да се отвори задачата в **Tasks**, а тя да остане там след затваряне и повторно отваряне на MyHub.
4. Върни се на **Начало → + → Бележка**. Въведи `Идея` и текст, после **Запази**. Провери я в **Notes**.
5. Натисни **+**, въведи незаписан текст, опитай да затвориш. MyHub трябва да поиска потвърждение.
6. Отвори Calendar, Notes, Tasks и Weather, за да потвърдиш, че предишните записи са налични. **+** не трябва да се вижда по време на редакция вътре в инструмент.
7. Включи самолетен режим и повтори проба със задача или бележка. Записът трябва да работи локално.
8. Направи **нов JSON Backup**, провери наличието му в Downloads, и го запази на безопасно място. Възстановяване не е необходимо да тестваш върху основните си данни.

## 6. Ако нещо не работи

- Ако се появи **v1.0.0**, провери дали `js/config.js` и `sw.js` действително са обновени в GitHub и дали приложението предлага нов Service Worker.
- Ако бутонът **+** липсва: провери дали `quick-add.css`, `js/quick-add.js` и `js/quick-add-core.js` са на правилните места.
- Ако получиш грешка при запис: **не изтривай базата**. Върни се към стария JSON архив само след отделна проверка, защото Restore заменя текущите данни.
- Ако страницата е празна: прегледай съответствието на всички имена и папки, най-вече `index.html`, `sw.js` и `js/app.js`.

## 7. Какво не се променя

- Няма нов сървър, API ключ, абонамент или акаунт.
- Няма промяна в структурата или версията на `myhub-local` (IndexedDB **v1**).
- Backup форматът остава **MyHub format 1** и архивите от предишните версии продължават да бъдат съвместими.
- Старите инструменти, настройки, любими и офлайн файлове са запазени.
- Интеграцията с Android Share Sheet не е включена във v1.1.0.
