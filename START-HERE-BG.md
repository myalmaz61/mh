# MyHub v1.0.0 — ръководство за Android + GitHub

**Подходящо за човек, който използва само Android телефон.** Не се изискват компютър, Android Studio, платени услуги или нов GitHub repository.

## 1. Запази данните, преди да обновяваш

1. Отвори инсталирания MyHub **v0.9.0** през същата икона и същия адрес, които вече използваш.
2. Отвори **Настройки → Изтегли JSON архив (Backup)**.
3. В Android **Files → Downloads** провери, че файл `MyHub-backup-....json` наистина съществува. Запази и второ копие, ако имаш възможност.
4. Не деинсталирай PWA и **не** избирай Chrome → Clear storage / Изтриване на данните. Не променяй GitHub Pages URL, име на repository или Chrome профил.

## 2. Кой ZIP да използваш?

- От **v0.9.0 към v1.0.0**: използвай `MyHub-v1.0.0-UPDATE-ONLY.zip`. Той има **само новите или променените файлове**, в правилните папки.
- За **нова инсталация**: `MyHub-v1.0.0.zip` съдържа пълния проект.
- Ако GitHub на телефона не позволява удобно качване: `MyHub-v1.0.0-FULL-SOURCE.md` дава **пълния код на всеки нов или променен текстов файл** за Copy/Paste. Не е необходимо да редактираш отделни редове.

## 3. Как да качиш обновлението само с телефона

1. Изтегли ZIP архива и го разархивирай с **Files** на Android.
2. Отвори `github.com` през **Chrome** и влез в съществуващото хранилище на MyHub.
3. При нужда избери **Chrome ⋮ → Desktop site**.
4. **В корена** (там, където е старият `index.html`) качи/замени тези файлове:
   - `index.html` (съществуващ)
   - `sw.js` (съществуващ)
   - `search.css` (**нов**)
   - `package.json` (съществуващ)
   - `README.md` и `START-HERE-BG.md` (документация)
5. В папката **`js`** качи/замени:
   - `app.js`, `config.js`, `i18n.js`
   - `search.js`, `search-core.js` (**нови**)
   - `notes.js`, `tasks.js`, `calendar.js`, `quick-list.js`, `bookmarks.js`
6. В папката **`tests`** качи файловете `.test.mjs` от ZIP. `search.test.mjs` е **нов**; останалите проверяват и новия номер на версията.
7. Избери **Commit changes**. Съхрани същите имена и папки. Останалите файлове не трябва да се променят.

**Важно за GitHub:** Не качвай ZIP като единичен файл вътре в хранилището. Не създавай вложена папка `MyHub-v1.0.0` над `index.html`. При замяна на файл може да се наложи да влезеш в неговата папка и да използваш `Add file → Upload files`. Ако този начин не е наличен на телефона, отвори съществуващия файл → иконата **Edit** (молив) → маркирай целия текст → постави **целия нов код** от Markdown файла → Commit. За нов файл използвай `Add file → Create new file` в правилната папка.

**Не променяй** GitHub Pages настройките (`main` / `(root)`) и не създавай ново приложение.

## 4. Провери версията

1. Използвай **съществуващата PWA икона**.
2. Ако се появи известие за нова версия, натисни **Обнови**, след което отвори MyHub отново.
3. В **Настройки → Версия** трябва да пише **v1.0.0**.
4. Ако още виждаш v0.9.0, провери GitHub → Actions/Pages за публикуването, имената на качените файлове и `sw.js`. Не изтривай данните на приложението като първа стъпка.

## 5. Тест на телефона (препоръчително)

1. Запази бележка с име **`Кафе за тест`**, а вътре напиши `мляко`.
2. Добави задача **`Купи мляко`** (може да бъде и изпълнена).
3. В Календар създай събитие **`Доставка в кафето`**, след което добави `картофи` в някой бърз списък.
4. Отвори **Начало → „Търси навсякъде…“**. Напиши `мляко`. Трябва да се покажат бележката и задачата. Натисни филтъра **„Бележки“** и после **„Задачи“**.
5. Натисни бележката от резултатите: трябва да се отвори **точно тя**, а не празна бележка. Върни се на началния екран, отвори търсенето и натисни задачата: трябва да се отвори **редакцията на същата задача**.
6. Потърси `доставка`: резултатът трябва да води към календарното събитие. Потърси `картофи`: трябва да се отвори правилният бърз списък.
7. Добави запазена връзка в Bookmarks и тествай търсене по заглавие или адрес. Филтърът **„Инструменти“** трябва да намира и „Калкулатор“.
8. Пусни **самолетен режим**. Отвори отново търсенето и потърси същите записи. То трябва да работи без интернет.
9. Провери, че старите ти бележки, задачи, календар и настройки са на мястото си. Направи **нов JSON Backup** и отново провери дали файлът е в Downloads.
10. Изтрий само пробните записи, които си създал, когато приключиш.

## 6. Защита на личните данни

- Universal Search **само чете** от Notes, Tasks, Calendar, Quick Checklists, Bookmarks и наличните имена на инструменти.
- Не се използват API, платени функции, trackers или cloud; търсенето не запазва история на написаните думи.
- **Същият IndexedDB** `myhub-local`, версия 1; не се изтриват или мигрират обекти.
- Същият **JSON Backup формат 1**; новото търсене не добавя нови полета.
- При повредени данни от отделен инструмент се показва предупреждение, без автоматично изтриване или презаписване.
- Възстановяването от стар JSON Backup може **да замени сегашните данни** с по-стари; прави текущ Backup преди Restore.
- При бъдещ Capacitor APK прехвърлянето е **JSON Export от PWA → Import в APK**.

## 7. Какво е проверено и какво остава

- `node --test`: **105 от 105 успешни автоматизирани теста**, включително 13 нови теста за търсенето.
- Изолираният екран за търсене е проверен в Chromium с тестови бележки, задачи, категории, избор на резултат и проверка срещу изпълнение на HTML от бележка.
- Пълната PWA не можа да се отвори през локалния HTTP тестов адрес в Chromium заради ограничение на работната среда. **Android Chrome/PWA проверката е необходима** и е описана в раздел 5.
